## Confirmed renderer issue and correction

The previous cache evicted after 48 textures and flushed the renderer on each
removal. A crowded scene could therefore decode the same graphics every frame.
The revised cache uses a 16 MiB byte budget, protects current-frame textures,
trims after presentation, and stores compact thumbnails at 84px rather than309px.
Row scoring also avoids copying the whole Player object.

On GitHub's desktop runner, --crowded-render-test drew 72 distinct unit images
for 120 frames. Both ordinary and software-composition runs reported:
- 76 initial image decodes;
- 0 repeat decodes after warm-up;
- 3,363,284 resident texture bytes.

Worst warmed frame: 1.753 ms ordinary; 3.416 ms software composition.
These are desktop runner measurements, NOT Miyoo timing or a device FPS claim.
The test establishes texture stability for this scene, not all gameplay stalls.
